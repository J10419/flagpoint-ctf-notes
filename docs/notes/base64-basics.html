看不懂，不代表被加密

遇到一段陌生字串時，先觀察它的表示方式。Base64 是編碼（encoding），可以把位元組表示成文字；本身不提供保密性，也不需要秘密金鑰。

本地示範

本篇兩段旗標是本專案原創的虛構教材。練習只處理這些文字，解碼結果不會送到伺服器。

編碼是在改變表示方式

標準 Base64 使用英文字母、數字、加號與斜線表示資料，結尾可能有填補字元（padding）等號。它讓二進位資料更方便放進需要文字的環境。

編碼後再解碼，是依公開規則還原原本的位元組；這與使用金鑰提供機密性的加密（encryption）不同。解碼結果也不保證一定是可閱讀的文字。

將下方字串作為 Base64 解碼輸入。用途是把文字表示還原；預期輸出為 flag{first_step}。

ZmxhZ3tmaXJzdF9zdGVwfQ==

  • 將整段貼入本頁實驗區並選擇解碼。
  • 檢查結果是否符合題意，而不是只因工具沒有報錯就認定成功。
  • 預期得到 flag{first_step}，再記下輸入、方法與結果。

若已安裝 Node.js，也能在本地執行下方示例。輸入相同字串，輸出同一個示範 flag；這段程式用來核對結果，不是嚴格格式驗證器。

javascript
Buffer.from('ZmxhZ3tmaXJzdF9zdGVwfQ==', 'base64').toString('utf8')

常見誤區

  • 看不懂就是加密：表示方式改變，不代表有保密性。
  • Base64 一定有等號：是否出現填補取決於資料長度及使用規格。
  • 有等號就一定是 Base64：還要檢查字母表、格式與解碼結果。
  • Base64 與 Base64url 完全相同：兩者字母表有差異，本頁實驗處理標準 Base64。
